# Grid Core Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@grid-master/core`, the framework-free TypeScript package: a pure layout engine (flow, four drop modes, resize, add/remove, narrow stacking) plus a vanilla-DOM controller (rendering, drag with placeholder/ghost/marker, resize) that the Angular and React wrappers will bind to.

**Architecture:** Two layers inside one package. `src/engine/*` is pure functions over `LayoutItem[]` with no DOM, so every rule in the spec is unit-tested in Node. `src/dom/*` is a controller (`createGrid`) that positions widgets with CSS grid, drives pointer interactions, and calls the engine to decide whether a drop/resize is allowed. Hit-testing is a pure function over rectangles so it is testable without real layout.

**Tech Stack:** TypeScript (strict), pnpm workspaces, Vitest (`node` env for engine, `happy-dom` for DOM tests), `tsc` for build. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-28-grid-design.md`

**Follow-up plans (not in this one):** Angular wrapper + Angular demo app; React wrapper. Both consume the `createGrid` API and DOM contract defined in Tasks 9–11.

## Global Constraints

- Core is framework-free: no Angular/React imports anywhere in `packages/core`.
- Layout model is an **ordered list**; array order is position. Input never carries x/y.
- Layout item: required `id`, `w`, `h`; optional `minW`, `minH` (default 1), `locked` (default false).
- Exactly one drop mode active: `'insert' | 'block' | 'shrink' | 'swap'`, changeable at runtime. Resize follows the same mode (`swap` resizes like `block`).
- **No widget other than the dragged one moves during drag.** Layout changes only on drop/resize release.
- Fixed row count (`maxRows`), when set, is a hard limit for drops, resizes, and adds.
- Narrow view (container width < `breakpoint`, default 640px): single column in list order; reordering there is temporary and never emits `onLayoutChange`.
- Mouse and touch via Pointer Events. Keyboard is out of scope.
- License MIT. Package name `@grid-master/core` is a working name (author picks final scope later).
- Pragmatic drag and drop is **not** used *(builder's call permitted by the spec)*: native HTML5 DnD can't give a fully controlled ghost or smooth touch, and it doesn't cover resize. Plain Pointer Events do both.

## Review Focus

- A layout item with `w` larger than `columns` (or below `minW`) → clamped into `[minW, columns]`, never overflowing. Test in Task 1.
- A layout entry with no matching element, or an element with no layout entry → no crash; the entry is kept and emitted unchanged; the element is hidden. Test in Task 9.
- Touch interrupted (`pointercancel`) or pointer released outside the grid mid-drag → drag cancelled, layout unchanged, ghost removed. Test in Task 10.
- `setLayout`/`setOptions` called while a drag is in progress → drag cancelled cleanly. Test in Task 10.
- Dropping a widget back onto its own spot → no `onLayoutChange` emitted. Tests in Tasks 3 and 10.

### Task 2: Flow (ordered list → positions)

**Files:**
- Create: `packages/core/src/engine/flow.ts`
- Test: `packages/core/test/engine/flow.test.ts`

**Interfaces:**
- Consumes: `LayoutItem`, `PlacedItem` (Task 1)
- Produces: `computeFlow(items: LayoutItem[], columns: number): PlacedItem[]`, `rowsOf(placed: PlacedItem[]): string[][]`, `totalRows(placed: PlacedItem[]): number`, `stackForNarrow(items: LayoutItem[]): PlacedItem[]`

Algorithm (spec "Core model", rows are bands):

```
x = 0, row = 0, rowTop = 0, rowHeight = 0
for item:
  if x > 0 and x + item.w > columns: rowTop += rowHeight; row++; x = 0; rowHeight = 0
  place at (x, rowTop, row); x += item.w; rowHeight = max(rowHeight, item.h)
totalRows = rowTop of last row + its rowHeight (0 for empty)
```

### Task 3: planDrop: Insert and Block, locked and maxRows rules

**Files:**
- Create: `packages/core/src/engine/drop.ts`
- Test: `packages/core/test/engine/drop.test.ts`

**Interfaces:**
- Consumes: `computeFlow`, `rowsOf`, `totalRows` (Task 2); types (Task 1)
- Produces: `planDrop(layout: LayoutItem[], config: EngineConfig, dragId: string, target: DropTarget): DropResult`

Semantics, shared by all modes:
- `{ index }` is a position in the list **with the dragged item removed** (`0..length-1`). It's valid for `insert`/`block`/`shrink`. `{ swapWith }` is valid only for `swap`. A mismatch, an unknown id, or an index out of range returns `invalid`.
- The dragged item is locked → `locked`.
- Every locked item must keep its index in the result, otherwise `locked`.
- If `maxRows` is set and `totalRows(result) > maxRows` → `max-rows`.
- Checks run in order: invalid → locked → mode rule → max-rows.
- **Block rule:** let `before = rowsOf(computeFlow(layoutWithoutDragged))` and `after = rowsOf(computeFlow(result))` with the dragged id removed from each row (dropping empty rows). If `after` ≠ `before`, return `no-room`. In other words, the dragged widget must fit without moving any other widget to a different row. The old spot closing up is allowed.

### Task 4: Shrink-to-fit

**Files:**
- Create: `packages/core/src/engine/shrink.ts`
- Modify: `packages/core/src/engine/drop.ts` (the `shrink` case)
- Test: `packages/core/test/engine/shrink.test.ts`

**Interfaces:**
- Produces: `shrinkRowToFit(row: LayoutItem[], fixedId: string, columns: number): LayoutItem[] | null`. It takes the items of one row in order. If their widths add up to more than `columns`, it shrinks the items other than `fixedId`, **nearest to `fixedId` first** (by distance in the row; on a tie, the left one first), each fully down to its `minW ?? 1` before moving to the next. Locked items never shrink. It returns `null` if the row can't fit.
- Used by Task 6 as well.

**Drop rule for `shrink`:** `rest = layout without dragged`, `rows = rowsOf(computeFlow(rest))`. The target row is the row of `rest[index]`, or the last row if `index === rest.length`. If `rest` is empty, the result is just the dragged item. Build the target row with the dragged item inserted at its position and call `shrinkRowToFit`. A `null` result means `no-room`. Otherwise write the shrunk widths back into the list with the dragged item at `index`. The locked and maxRows checks from Task 3 still apply.

### Task 6: planResize

**Files:**
- Create: `packages/core/src/engine/resize.ts`
- Test: `packages/core/test/engine/resize.test.ts`

**Interfaces:**
- Consumes: `computeFlow`, `rowsOf`, `totalRows`, `shrinkRowToFit`
- Produces: `planResize(layout: LayoutItem[], config: EngineConfig, id: string, size: { w: number; h: number }): DropResult`

**Rules:** `size` is clamped to `w ∈ [minW, columns]` and `h ≥ minH`. A locked item returns `locked`, and an unknown id returns `invalid`. Then by mode:
- `insert`: apply the size and reflow.
- `block` and `swap`: apply the size. If the row membership (`rowsOf`) changes, return `no-room`. Height changes keep the rows as they are, so they're allowed.
- `shrink`: apply the size and, if its row now overflows, call `shrinkRowToFit(row, id, columns)`. A `null` result means `no-room`.
- Last, the maxRows check.

### Task 8: Hit-testing (pure)

**Files:**
- Create: `packages/core/src/engine/hit.ts`
- Test: `packages/core/test/engine/hit.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface ItemRect { id: string; left: number; top: number; right: number; bottom: number } // container-relative px
  export type Marker =
    | { kind: 'line'; left: number; top: number; width: number; height: number } // width 0 = vertical line, height 0 = horizontal
    | { kind: 'outline'; id: string };
  export interface Hit { target: DropTarget; marker: Marker }
  export function resolveTarget(rects: ItemRect[], point: { x: number; y: number }, dragId: string, mode: DropMode, axis: 'x' | 'y'): Hit | null;
  ```
  `rects` are in list order and include the dragged item, which is skipped. Indexes are positions in the list without the dragged item.

**Rules:**
- In `swap` mode: if the pointer is inside an item's rect (other than the dragged one), return `{ swapWith }` with an outline marker. Otherwise return `null`.
- In other modes, when the pointer is inside an item: with `axis: 'x'`, the left half means "before" (the line is at `rect.left`, `height` = rect height) and the right half means "after" (the line is at `rect.right`). With `axis: 'y'` (narrow view), it's the top/bottom halves, and the line is horizontal with `width` = rect width.
- When the pointer is in empty space beside items (`axis: 'x'`): pick the nearest item whose vertical range contains `point.y` and whose `right ≤ point.x`, and drop after it.
- When the pointer is below every item (or no other items exist): drop at the end of the list. The line goes after the last item, or at `{ left: 0, top: 0 }` when the list is empty.
- Anything else returns `null`.

### Task 10: Drag interaction (placeholder, ghost, marker)

**Files:**
- Create: `packages/core/src/dom/drag.ts`
- Modify: `packages/core/src/dom/controller.ts` (wire it in)
- Test: `packages/core/test/dom/drag.test.ts` (happy-dom)

**Interfaces:**
- Consumes: `resolveTarget` (Task 8), `planDrop`, `layoutsEqual`, controller internals

**Behavior:**
- `pointerdown` on the handle (or on the widget, if it has no handle) of an unlocked widget arms the drag. Locked widgets never arm. The drag starts after the pointer moves 4px. Handles and widgets without handles get `touch-action: none`.
- On start:
  - The widget stays where it is and gets the `gm-item--placeholder` class (its content is hidden and it gets a dashed outline).
  - A `cloneNode(true)` ghost with the class `gm-ghost` is appended to `document.body`. It has `position: fixed`, `pointer-events: none` and the same size as the widget, and it follows the pointer, keeping the grab offset.
  - No other widget's styles change.
- On move:
  - Build `ItemRect[]` from each widget's `getBoundingClientRect()`, made relative to the container rect.
  - Call `resolveTarget` with `axis` set to `'y'` in narrow view and `'x'` otherwise.
  - For any hit, call `planDrop`. In narrow view, the mode is `'swap'` if the active mode is swap and `'insert'` otherwise, with `columns: 1` and no `maxRows`.
  - Show `.gm-marker` positioned from the hit's marker. For outline hits, add `gm-item--swap-target` to the target instead.
  - Add `gm-marker--blocked` when the plan isn't ok, and hide the marker when there's no hit.
- On `pointerup`:
  - If the plan is ok and `!layoutsEqual`: in wide view, commit and emit `onLayoutChange`. In narrow view, store a temporary narrow order and re-render without emitting.
  - Always clean up: remove the ghost, the placeholder class and the marker.
- Cancel without any change on `pointercancel`, the Escape key, a `pointerup` with no valid hit (including outside the container), `setLayout`/`setOptions` mid-drag, and `destroy`.
- Tests dispatch `new PointerEvent(type, { clientX, clientY, bubbles: true })`. Call `setPointerCapture` only if it exists. Stub `getBoundingClientRect` on the container and the widgets.
