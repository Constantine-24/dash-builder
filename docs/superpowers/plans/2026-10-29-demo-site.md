# Demo Site (GitHub Pages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public demo site for GitHub Pages. It has a "clean light" landing page with a live vanilla grid and a drop-mode switch, feature cards, framework tabs (Vanilla in-page; Angular and React as real-package mini-apps in iframes, each with its own mode switch) and install links. A GitHub Actions workflow publishes it.

**Architecture:**
- **Shared kit.** A private workspace package `@grid-master/demo-kit` holds the shared demo content: the block data, the per-mode hint texts, the site config helpers and the block/theme CSS. All four grids use it, so they can't drift apart.
- **`site/`.** A private Vite package for the landing page (vanilla core, no framework) and the React tab app (a second Vite entry at `react/`).
- **Angular tab app.** A third project, `site-demo`, in the existing Angular workspace.
- **Assembly.** A node build script works out the base path from `GITHUB_REPOSITORY`, builds both Vite entries and the Angular app with that base, and assembles everything into `site/dist/`. The workflow uploads `site/dist/`.

**Tech Stack:**
- Vite 8 (+ `@vitejs/plugin-react` 6)
- TypeScript 7 for the kit and site; the Angular workspace stays on TS ~6.0 / Angular 22
- Vitest 5 + happy-dom
- GitHub Actions: `actions/checkout`, `pnpm/action-setup`, `actions/setup-node`, `actions/upload-pages-artifact`, `actions/deploy-pages`

**Spec:** `docs/superpowers/specs/2026-10-29-demo-site-design.md`

## Global Constraints

- **Look: "clean light"**
  - A white background, slate text `#0f172a`, thin borders `#e2e8f0`, one accent `#2563eb`.
  - The refused-drop colour is the core default red.
  - The theme lives in CSS custom properties in `@grid-master/demo-kit/theme.css`, shared by all pages.
- **The hero grid is draggable on first view** above the fold at 1280×800. The hero never waits for Angular or React: iframes load lazily when their tab first opens.
- **The four grids show the same blocks and behave the same.** Block data, hint texts and block CSS come only from `@grid-master/demo-kit`.
- **The hero controls drive only the hero.** The Vanilla tab, the Angular app and the React app each have their own drop-mode switch. The page never syncs state into iframes.
- **No debug JSON in the hero.** Layout JSON appears only in the "Layout is JSON" feature card (a collapsible `<details>`).
- **Base path:**
  - Base is `/<repo>/` when `GITHUB_REPOSITORY=<owner>/<repo>` is set, else `/`.
  - The repo URL is `https://github.com/<owner>/<repo>` when the variable is set, else no GitHub link.
  - npm links are hidden unless `SHOW_NPM=1`.
  - Every asset URL and iframe `src` respects the base.
- The library name "grid-master" is defined once, in `demo-kit` (`SITE.name`).
- The existing demos are not modified: `packages/core/examples/vanilla.html`, the Angular `demo` project, and `packages/react/demo/`.
- Use the newest versions the repo's pnpm `minimumReleaseAge` policy accepts. Every package's `test` script is non-watch. CI uses Node 22 and pnpm 12.11.2 with `pnpm install --frozen-lockfile`.
- The page chrome (nav, segmented controls, tabs, toggles, `<details>`) is keyboard-usable, with visible focus.
- The site is responsive. Below 640px the hero grid naturally shows the narrow (stacked) view.

## Review Focus

1. **Served from a sub-path** (`/grid-master/`), no asset, CSS, iframe or Angular chunk 404s. This is pinned by `site/scripts/check-dist.mjs` in Task 6, plus the controller's browser check.
2. **The hero's mode switch and hint stay in sync**, and every hint matches the core README's description of its mode. Tested in Task 2.
3. **Tab iframes load only once, on first open.** Switching tabs back and forth doesn't reload them. Tested in Task 3.
4. **The Angular app's `baseHref` and lazy chunks** resolve under `<base>angular/`. Pinned by `check-dist.mjs` in Task 6 (the base-href in `angular/index.html`, and every `<script src>` file exists).
5. **A visitor on a phone width** sees the narrow hero grid and can still use the tabs. Tested in Task 2 (narrow class at 480px) and in the controller's browser check.

  - `SITE = { name: 'grid-master' }`
  - `siteConfig(env: { GITHUB_REPOSITORY?: string; SHOW_NPM?: string }): SiteConfig`

    - showNpm: `env.SHOW_NPM === '1'`

    - It also sets `--gm-marker-color: var(--site-accent)` and `--gm-placeholder-border: 2px dashed #94a3b8`.
  - `blocks.css`:
    - `.demo-block` (fills its widget, padding, radius, border, `cursor: grab`)
    - modifiers `.demo-block--locked` (striped, `cursor: not-allowed`), `.demo-block--selected`
    - `.demo-block__title`, `.demo-block__value`, `.demo-block__chart` (an inline SVG sparkline), `.demo-block__grip` (the handle), `.demo-block__form`
    - Every rule uses only `theme.css` variables plus each block's accent, passed as `--block-accent`.
